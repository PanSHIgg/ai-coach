## 一、变更原因

原文档中邀请相关表述存在多处冲突：

| 冲突点     | 表述 A        | 表述 B         |
| ------- | ----------- | ------------ |
| 邀请如何算有效 | 完成 1 次拍照记录  | 完成建档         |
| 奖励时长    | 10 人解锁永久    | 单人奖励上限 180 天 |
| 发放节奏    | 实时 / 次日批量   | 未统一          |
| 是否多级裂变  | 有循环裂变       | 未统一          |
| 权益档位    | 基础/进阶/深度/终身 | 仅泛称"升级"      |

为保证文档口径一致、开发可执行，现统一为以下最终规则。

## 二、最终邀请规则（统一口径）

### 1. 有效邀请定义

**被邀请人注册成功即算有效邀请。**

- 不需要完成建档
- 不需要拍照记录
- 不要求后续活跃
- 只需被邀请人完成注册

### 2. 权益档位

| 累计有效邀请人数 | 权益（AI 对话次数） | 说明         |
| -------- | ----------- | ---------- |
| 0 人      | 10 次/日      | 所有新用户默认基础版 |
| 达到 1 人   | 20 次/日      | 首次邀请即升级    |
| 达到 3 人   | 40 次/日      | 邀请 3 人解锁   |
| 达到 10 人  | 不限次         | 永久解锁终身版    |

### 3. 只算直接邀请

- A 邀请 B：A 获得权益
- B 邀请 C：与 A 无关
- C 邀请 D：与 A、B 均无关
- 不做多级裂变，不设 180 天上限，不要求被邀请人活跃续期

### 4. 发放方式

- **实时生效**：被邀请人注册成功那一刻，邀请人权益立刻升级
- 不依赖日终批量任务
- 权益长期有效，不回收、不设有效期

### 5. 被邀请人的权益

- 被邀请人注册后默认享受基础版权益（10 次/日）
- 如需升级，自行邀请他人

## 三、文档逐项变更明细

### 1. §2.3.3 邀请裂变流程

**变更前：**

- 有效邀请须完成拍照记录/建档
- 单人奖励上限 180 天
- 邀请权益次日批量发放
- 存在多级裂变逻辑

**变更后：**

- 注册即有效
- 只算直接邀请
- 实时生效
- 1 人 20 次 / 3 人 40 次 / 10 人永久
- 无期限、无活跃要求

### 2. §2.4 异常场景

**变更前：** "邀请人达到上限"

**变更后：** 已达终身版后，分享按钮文案改为"继续邀请帮助更多人"

### 3. §2.5 验收标准

**变更前：** "邀请 2 人 → 进阶版 90 天"

**变更后：**

- 被邀请人注册成功即判为有效邀请
- 1 人 → 20 次/日；3 人 → 40 次/日；10 人 → 不限次
- 防刷机制返回错误码 4102

### 4. §2.1 功能清单

**变更前：** 首页仅列"热量账户"

**变更后：** 与 §5.1 保持一致：热量账户总览 + 健康评分环 + 摄入/运动明细 + AI 教练卡片 + 快捷服务

### 5. §7.2 invite 表

**变更前字段：**

- status：0=已注册未建档，1=已建档有效
- reward_granted：是否已发放奖励
- 存在多级裂变相关字段

**变更后字段：**

| 字段         | 类型        | 说明          |
| ---------- | --------- | ----------- |
| id         | BIGINT    | 主键          |
| inviter_id | BIGINT    | 邀请人 ID      |
| invitee_id | BIGINT    | 被邀请人 ID     |
| status     | SMALLINT  | 恒为 1（注册即有效） |
| created_at | TIMESTAMP | 创建时间        |

约束：

- `CHECK (inviter_id <> invitee_id)` 防止自邀请
- `UNIQUE (invitee_id)` 防止重复绑定

### 6. §7.2 user_benefit 表

**变更前：** 含 valid_from / valid_to 有效期字段

**变更后：** 删除有效期字段，由注册回调实时 +1 并重算 tier

### 7. §7.2 ai_knowledge 表

**变更前：** embedding 字段 vector(1536) 与 jsonb 占位并存

**变更后：** 统一使用 JSONB，注释写明"二期启用 pgvector 后迁移为 vector(1536)"

### 8. §8.4.9 邀请进度接口

**变更前示例：**

```json
{
  "next_tier_need": 2,
  "reward": "进阶版90天"
}
```

**变更后示例：**

```json
{
  "next_tier_need": 10,
  "reward": "终身版不限次"
}
```

档位阈值统一由后端配置 `INVITE_TIERS = [1, 3, 10]`，前端不硬编码。

### 9. §13.3 业务默认规则

**变更前：**

- 拍照记录算有效邀请
- 次日批量发放

**变更后：**

- 注册即有效
- 实时生效
- 长期有效
- 不做多级裂变
