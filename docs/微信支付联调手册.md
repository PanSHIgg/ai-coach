# 微信支付联调手册（Phase 5 / F1）

> 适用范围：小程序 JSAPI 支付（下单 → 拉起支付 → 回调 → 核销 → 退款）在 **真实微信支付商户环境** 下的接入与排查。
>
> **重要声明：本手册与配套代码在沙箱内未执行真实联调。** 沙箱无真实商户号 / APIv3 密钥 / 商户私钥 / 平台证书 / 真机，
> `backend/app/services/wechat_pay.py` 的真实统一下单 HTTP 调用路径 **未联网执行**；已验证的部分仅限
> 「纯标准库实现的 RSA-SHA256 签名 / 验签 + AES-256-GCM 解密」单测（见 §7）与退款状态流转（§5）。

---

## 1. 代码结构

| 文件 | 职责 |
| --- | --- |
| `backend/app/services/wechat_pay.py` | APIv3 接入骨架：配置读取、请求签名（`WECHATPAY2-SHA256-RSA2048`）、回调验签、`AES-256-GCM` 资源解密、JSAPI 预下单（含无密钥降级） |
| `backend/app/services/order_service.py` | `pay_order`（mock / 真实预下单分流）、`refund_order`（2→5 幂等）、`handle_notify` / `redeem_order` |
| `backend/app/api/v1/endpoints/orders.py` | `/order`、`/order/{id}/pay`、`/order/notify`、`/order/{id}/redeem`、`/order/{id}/refund`、`/order/list` |
| `backend/tests/test_pay_wechat.py` | 退款闭环 + 签名/验签/解密单测 |

**实现约束**：仅使用 Python 标准库（`hashlib` / `hmac` / `base64` / `secrets` / `json`），
不引入任何未安装的三方 SDK（沙箱环境无 `cryptography` / `wechatpay` 包，`requirements.txt` 亦未加依赖）。
RSA-SHA256（PKCS#1 v1.5）与 AES-256-GCM 为自实现，只覆盖微信支付 APIv3 所需子集。

## 2. 配置项清单

> `core/config.py` 为共享文件（冻结，禁改）。已有的 `WECHAT_APPID` / `WECHAT_MCH_ID` / `WECHAT_PAY_KEY` 走 `Settings`；
> 其余扩展项由 `wechat_pay.load_config()` 以 **同名环境变量 / `Settings` 宽字段** 读取，无需改 config。

| 配置项 | 读取来源 | 说明 |
| --- | --- | --- |
| `WECHAT_APPID` | `Settings` / env | 小程序 AppID |
| `WECHAT_MCH_ID` | `Settings` / env | 商户号（mchid） |
| `WECHAT_PAY_KEY` | `Settings` / env | **APIv3 密钥**（32 字节） |
| `WECHAT_MCH_SERIAL_NO` | env（扩展） | 商户 API 证书序列号 |
| `WECHAT_MCH_PRIVATE_KEY` | env（扩展） | 商户私钥 PEM **内容**（`-----BEGIN` 开头时优先取内容） |
| `WECHAT_MCH_PRIVATE_KEY_PATH` | env（扩展） | 商户私钥 PEM **文件路径**（二选一） |
| `WECHAT_PLATFORM_PUBLIC_KEY` | env（扩展） | 微信支付平台公钥 PEM 内容 |
| `WECHAT_PLATFORM_CERT_PATH` | env（扩展） | 平台证书文件路径（`load_public_key` 支持 X.509 证书，自动提取 SPKI） |
| `WECHAT_NOTIFY_URL` | env（扩展） | 回调通知地址（须 HTTPS、公网可达） |
| `PAY_MOCK_MODE` | `Settings` | 沙箱支付开关，见 §3 |

`configured` 判定：`mch_id` + `serial_no` + `private_key_pem` + `api_v3_key` 齐备才视为可真实接入。

## 3. `PAY_MOCK_MODE` 开关语义

| 取值 | `POST /api/order/{id}/pay` 行为 | 参数特征 |
| --- | --- | --- |
| `True`（沙箱/演示） | 直接推进支付成功（`status` 1→2、生成核销码、券 `used_at`、扣库存），**不请求微信** | `pay_params.mock=true`，`paySign` 为 HMAC 伪造（仅供演示） |
| `False`（真实） | 调用 `wechat_pay.prepare_payment` 预下单；订单保持待支付，等 `/order/notify` 推进 | 已配置 → 真实 `prepay_id` + RSA `paySign`；未配置 → `degraded=true` 占位（**不含** `mock` 标记） |

- **生产必须 `PAY_MOCK_MODE=false`**：`app/main.py` 在 `ENV=prod` 且 `PAY_MOCK_MODE=True` 时启动即 `raise`（IS-001）。
- 未配置密钥时的降级：`prepare_payment` 返回 `PrepayResult(degraded=True, reason=...)`，`pay_params` 携带 `degraded=true`，
  **绝不伪造真实签名**；调用方（前端/运维）可据此判别并提示「支付未就绪」。

## 4. 真机联调步骤

1. **申请与开通**：完成微信支付商户入驻，获取 `mch_id`；在商户平台申请 API 证书（得到证书序列号 `serial_no` 与 `apiclient_key.pem` 私钥）。
2. **设置 APIv3 密钥**：商户平台「API 安全」设置 32 位 `api_v3_key`（写入 `WECHAT_PAY_KEY`）。
3. **配置环境变量**（生产经密钥管理注入，切勿入库/入日志）：
   ```bash
   export WECHAT_APPID=wx************
   export WECHAT_MCH_ID=190000****
   export WECHAT_PAY_KEY=************************  # 32 位
   export WECHAT_MCH_SERIAL_NO=**********************
   export WECHAT_MCH_PRIVATE_KEY_PATH=/etc/wechat/apiclient_key.pem
   export WECHAT_NOTIFY_URL=https://api.example.com/api/order/notify
   export PAY_MOCK_MODE=false
   export ENV=prod
   ```
4. **平台证书 / 公钥准备**（用于回调验签）：从微信支付下载平台证书，或导出公钥：
   ```bash
   openssl x509 -in wechatpay_platform_cert.pem -pubkey -noout > platform_pub.pem
   export WECHAT_PLATFORM_CERT_PATH=/etc/wechat/wechatpay_platform_cert.pem
   # 或：export WECHAT_PLATFORM_PUBLIC_KEY="$(cat platform_pub.pem)"
   ```
5. **域名与回调**：`WECHAT_NOTIFY_URL` 必须 HTTPS 且公网可达；确保网关把 `/api/order/notify` 的原始请求体**原样**透传给后端（验签依赖原始 body，不能反序列化后重排）。
6. **拉起支付**：小程序调用 `wx.requestPayment`，透传后端返回的 `timeStamp/nonceStr/package/signType=paySign`（`signType=RSA`）。
7. **验真**：支付成功后建议前端调用 `/order/list` 或后端对账确认 `status=2`，**不可仅凭前端回调**判定成功（回调可能被伪造，见 §6）。

## 5. 退款流程

- 接口：`POST /api/order/{id}/refund`，可选 body `{"reason": "..."}`（≤128 字）。
- 状态机：**仅** `2 已支付待核销 → 5 已退款`；`FOR UPDATE` 锁订单行防并发重复退款。
- 语义与错误码：
  | 场景 | 结果 |
  | --- | --- |
  | 成功 / 已退款重复申请 | `200`，`data={order_id,status:5,refunded:true}`（幂等，不重复流转） |
  | 订单不存在 | `3001` / HTTP 404 |
  | 非本人订单 | `1002` / HTTP 403 |
  | 状态非 2/5（未支付、已完成、已取消）| `2001` / HTTP 422 |
- 已退款订单不可再核销（`redeem_order` 对 `status=5` 返回 `5002`）。
- **【假设】** 因订单表结构冻结（无退款字段列），退款**仅做状态流转**，不回滚库存/券。
  真实接入微信退款 APIv3（`/v3/refund/domestic/refunds`）时，建议在 `wechat_pay.py` 增补 `refund()` 并在此处串接。

## 6. 验签与幂等排查

- **回调验签**：`wechat_pay.parse_notify(headers, raw_body)` 先校验 `WECHATPAY-TIMESTAMP / WECHATPAY-NONCE / WECHATPAY-SIGNATURE`
  （报文 `timestamp\nnonce\nbody\n` 的 RSA-SHA256），再 `AES-256-GCM` 解密 `resource`。任一步失败抛 `WeChatPayError`。
- **常见验签失败原因**：body 被框架做过 JSON 重排；用了错误的平台证书/公钥；时间戳偏差过大（应做重放窗口校验）；密钥/证书环境变量未生效。
- **幂等**：`handle_notify` 对 `status>=2` 直接应答成功，库存只扣一次；已取消订单收到迟到回调返回 `5003`。
- **金额防篡改**：回调金额与订单 `pay_amount` 不一致 → `2001`（对既有逻辑无改动）。

## 7. 已验证 / 未执行

**已在沙箱执行（真实跑通）**
- `backend/tests/test_pay_wechat.py`：自造 RSA 密钥对（纯标准库生成）验证请求签名/回调验签；篡改报文体/签名字段验签失败；
  AES-256-GCM 使用 NIST AES-256-GCM Test Case 14 向量解密正确 + 篡改 tag 认证失败；退款 6 场景。
- 自实现密码学已与 `openssl` 交叉验证：本实现签名经 `openssl dgst -sha256 -verify` 返回 `Verified OK`，反之亦然；
  AES-GCM 与 NIST TC13/TC14 输出一致。
- 契约自检：`from app.main import app; '/api/order/{id}/refund' in app.openapi()['paths']` → `True`。

**未执行（原因）**
- **真实微信联调**：沙箱无商户号/APIv3 密钥/证书/真机，`prepare_payment` 的真实 `httpx` 统一下单路径未联网执行；
  平台证书下载/轮换、回调公网可达性、`wx.requestPayment` 真机拉起均未验证。
- 微信侧退款 API、账单对账、证书自动更新（`/v3/certificates`）尚未实现，属后续硬化项。

## 8. 排查速查

| 现象 | 排查方向 |
| --- | --- |
| `degraded=true` | 检查 §2 四项必填是否齐备（尤其 `WECHAT_MCH_SERIAL_NO` 与私钥 PEM 是否被正确注入） |
| 统一下单 4xx | 检查 `out_trade_no` 唯一、金额单位（分）、`appid`/`mchid` 绑定关系、`payer.openid` 是否传入 |
| 回调 401/验签失败 | 原始 body 透传、平台证书是否最新、时间戳窗口 |
| 支付后订单仍待支付 | 回调未达/验签失败；先查日志，再人工触发对账 |
| 退款 2001 | 订单非「已支付待核销」（未支付/已完成/已取消） |
| 退款 1002 | 非本人订单（行级权限） |
