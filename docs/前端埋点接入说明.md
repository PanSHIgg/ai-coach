# 前端埋点接入说明（Phase 5 / F3 · miniapp）

> 口径真源：`docs/埋点与指标口径.md`（事件名 / 属性名 / 六项指标）。
> 接口契约：`POST /api/track`（`TrackIn`/`TrackEventIn`，批量 1~50，允许匿名）。

## 1. 埋点封装 `miniapp/src/utils/track.ts`

- `track(event, properties?)`：默认写入内存缓冲，延迟合并批量上报（**≤50 条/批**，达上限立即上报），
  可 `flush()` 立即上报（返回 Promise，可 await）。
- `device_id`：本地生成并持久化（`uni.getStorageSync('ai_coach_device_id')`），随批上报；
  匿名事件（`scan_in` 等）据此做设备级去重。
- `platform`：小程序=1 / H5=2，用 uni-app 条件编译（`// #ifdef H5`）区分，双端均能构建。
- **匿名可用**：不带 token 也可上报（后端 `get_optional_user` 自动关联或置空）；
  带 token 时自动附 `Authorization: Bearer`，无需页面特殊处理。
- **失败静默降级**：入队 / 存储 / 上报全链路 try/catch，失败丢弃批次，绝不阻塞 UI、不弹错、不重试轰炸。
- mp-weixin：额外镜像到微信自定义分析 `wx.reportEvent`（用 `// #ifdef MP-WEIXIN` 包裹，运行时探测可用性，失败忽略）。

## 4. 仍缺的异常态 / 埋点缺口

- **`ai_rating`（AI 满意度分子）**：AI 对话页当前**无评分 UI 入口**，本次**未新增 UI**（遵守"不为埋点新增页面/大改 UI"），
  故该事件**未接入**；需产品补充评分交互后再插桩。
- **`invite_share` / `invite_accept`（K 因子）**：miniapp 暂无邀请裂变落地页（均为 Phase 3 占位），未接入。
- **`scan_in` 触发依赖扫码参数**：仅在 `merchant/detail` 的 `onLoad` 检测到 `scene` 时上报；
  非扫码路径（列表点进详情）不会误报，符合"扫码转化率分母"口径。
- **上报失败无本地补传**：按契约要求"失败静默降级"，不做持久化重传；弱网下事件可能丢失。

## 5. 写接口幂等头 `Idempotency-Key`（P2-2 澄清）

- **现状**：miniapp（含 H5/小程序）**当前均未发送 `Idempotency-Key`**，admin 亦未发送；因此后端的
  幂等中间件对现有客户端不生效，属**「协作式幂等」**而非服务端强制防重放。无 key 时的重放风险由
  「支付/核销状态机 + 限流 + 内容审核」兜底（详见 `docs/接口冻结说明.md` §3.3）。
- **接入建议**：写操作（下单/支付/发帖等）在发起前生成唯一 key（UUID）并随请求头
  `Idempotency-Key` 发送；**同一次逻辑操作的所有重试复用同一个 key**，成功后丢弃、失败重试继续复用
  （服务端在响应 ≥400 时释放该 key，故失败重试不会被 409/4002 误拦）。
