# 第六部分：技术架构方案

## 6.1 技术选型

| 层     | 选型                                                  | 理由                                             |
| ----- | --------------------------------------------------- | ---------------------------------------------- |
| 前端    | uni-app（Vue3 + TypeScript）                          | 一套代码编译微信小程序 + H5，后期可编译 App，符合"小程序优先+原生 App 预留" |
| UI    | uni-ui + 自写组件（样式按第四部分令牌）                            | 无设计师，组件样式完全自定义                                 |
| 状态管理  | Pinia                                               | 轻量，配合 Vue3                                     |
| 后端    | Python 3.12 + FastAPI                               | 生态好、AI/数据科学库丰富、异步高性能                           |
| ORM   | SQLAlchemy 2.0 + Alembic                            | 迁移友好                                           |
| 数据库   | PostgreSQL 16                                       | JSONB 存动态档案/配置，数组存标签，全文检索                      |
| 缓存    | Redis 7                                             | 会话、热量账户快照、接口限流、热点食物库                           |
| 对象存储  | 腾讯云 COS                                             | 食物照片、商家图、用户头像                                  |

| 部署    | Docker Compose（首期）→ K8s（规模化）                        | 单机起步，后续平滑升级                                    |
| 反向代理  | Nginx                                               | HTTPS、静态资源、负载                                  |
| CI/CD | GitHub Actions + 腾讯云轻量服务器                           | 自动测试、构建、部署                                     |

## 6.2 系统分层

```
小程序/管理后台 → Nginx → API 网关（FastAPI） → 业务服务层
   ├── 用户服务（档案、权益、邀请）
   ├── 记录服务（饮食/运动/体重，写热量账户）
   ├── AI 服务（对话、饭点决策、RAG、视觉识别）
   ├── 热量服务（BMR/TDEE/NEAT/EAT/TEF 计算 + 步数校准）
   ├── 商家服务（目录、SKU、价格区间、权重、LBS）
   ├── 交易服务（订单、支付、券核销）
   ├── 内容服务（社区、五种社交、动态审核）
   └── 通知服务（订阅消息、提醒调度）
        ↓
  PostgreSQL + Redis + COS + 消息队列
```

## 6.3 关键模块设计

### 6.3.1 热量账户

- 账户快照采用**写时重算（recompute_day）+ 读兜底**，等效达成"打开即得、不重复全量重算"目标（原设计为 0 点定时任务生成 `daily_snapshot`，实现取等效方案）。
- 写入触发：饮食记录新增/编辑/删除 → 重算当日摄入 → 更新环形图。运动记录同理。
- 预算 = BMR × PAL；TEE = BMR×PAL + EAT + TEF（TEF=摄入×10%）。
- 缺口 = 摄入 - TEE，负值为热量缺口（有利减重）。

### 6.3.2 视觉识别 + 知识库

- 食物库：`food` 表 1700+ 条，含热量、蛋白、脂肪、碳水、GI、分类；搜索走 PostgreSQL 全文检索 `tsvector` + 别名表 `food_alias`。
- 识别流程：上传照片 → COS → 视觉 API 返回候选类目 → 匹配 `food` 表 → 置信度 < 0.7 时让用户确认 → 写入记录。
- AI 对话：LangChain + Milvus/PGVector（【假设】首期用 PGVector 省一套组件）+ RAG 检索知识库；系统提示词固定：身份为"AI 饮食教练"、只答体重管理、超限/疾病类引导就医。

### 6.3.3 步数校准 NEAT

- 四层融合：状态选择（粗调）→ 微信步数（精调）→ 穿戴设备（微调，二期）→ 体重变化（终极校准，周度反推）。
- 校准公式：基础 NEAT = MET_state × 体重 × 非睡眠小时；步数校准：按每小时步频映射 MET（散步 2.5 / 快走 4.3 / 跑步 8.0），逐时累加得 NEAT_calibrated，与状态法结果加权（步数占比 0.6、状态 0.4，有权重>0 时）。

### 6.3.4 商家与价格区间

- 标准目录 `sku_catalog` 由平台运营维护，商家只选不选建。
- 商家定价时，后端校验 `price BETWEEN min_price AND max_price`，超出返回 422 + code 2001。
- 权重分 = 拉新贡献 40% + 券贡献 40% + 过程贡献 20%；前 20% 战略合作独家区域，前 50% 优选合作保护，连续零贡献清退。

### 6.3.5 券池

- 券统一入 `coupon_pool`，用户只能从邀请任务/平台补贴获得，不外发。核销码 UUID，唯一索引。
- 核销：商家扫码（或手动输入）→ 校验归属商家、未用、未过期、满足门槛 → 标记已用 → 释放订单锁定库存。

### 6.3.6 安全

- 认证：微信小程序 `code2session` 换 `openid`，签发 JWT（access 2h + refresh 7d）。
- 接口：HTTPS 全站；敏感操作签名；CORS 白名单；SQL 参数化（ORM 天然防注入）。
- 限流：全局 100 次/分钟/IP；AI 对话 20 次/分钟/用户；登录 10 次/分钟/IP。
- 内容安全：用户发帖/上传图走微信 `security.msgSecCheck` + `imgSecCheck`，违规进入审核队列。
- 隐私：手机号加密存储；默认匿名身份；删除账号级联清除可清除数据；日志脱敏。

## 6.4 部署架构

单机起步：Nginx + FastAPI（uvicorn 多 worker）+ PostgreSQL + Redis + Celery worker（异步任务）。COS 走外网。监控用 Prometheus + Grafana（资源/接口耗时），日志用 Loki（或文件 + 集中收集，【假设】首期落文件，Cron 打包上传 COS）。

## 6.5 第三方依赖清单

微信小程序 API（登录、支付、订阅消息、内容安全、步数）、腾讯云 COS、视觉识别 API、DeepSeek/通义千问、地图（LBS 用腾讯地图）、可选智能硬件 OpenAPI。

# 第七部分：数据库设计

## 7.1 表清单

`user`（用户）、`user_auth`（第三方登录）、`body_profile`（身体档案）、`weight_record`（体重记录）、`food`（食物库）、`food_alias`（食物别名）、`meal_record`（饮食记录）、`sport_record`（运动记录）、`step_record`（步数记录）、`daily_snapshot`（每日热量快照）、`ai_dialog`（AI 对话）、`ai_knowledge`（知识库）、`merchant`（商家）、`sku_catalog`（标准目录）、`merchant_sku`（商家SKU）、`coupon`（券）、`coupon_pool`（券池）、`order`（订单）、`order_item`（订单项）、`redeem_log`（核销日志）、`invite`（邀请关系）、`user_benefit`（用户权益）、`community_post`（动态）、`community_group`（兴趣社群）、`supervise`（监督关系）、`battle`（约战）、`challenge`（挑战赛）、`challenge_join`（挑战赛参与）、`review`（审核）、`admin_user`（运营账号）、`config`（全局配置，**预留未启用：暂无 ORM 模型与业务引用**）、`subscription`（订阅，Phase 3 新增）、`leaderboard`（排行榜，Phase 3 新增）、`track_event`（埋点事件，Phase 5 新增）、`community_comment`（动态评论，Phase 4 新增）、`community_like`（动态点赞，Phase 4 新增）。

> 合计 **36 表**，与 `data/sql/001_schema.sql`（36 个 `CREATE TABLE`）对齐；Phase 3~5 新增的 5 表为 `subscription`、`leaderboard`、`track_event`、`community_comment`、`community_like`。

## 7.2 建表 SQL

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pg_trgm";

-- 用户
CREATE TABLE "user" (
  id BIGSERIAL PRIMARY KEY,
  openid VARCHAR(64) UNIQUE,
  unionid VARCHAR(64),
  phone_hash VARCHAR(128),
  nickname VARCHAR(64),
  avatar_url TEXT,
  gender SMALLINT DEFAULT 0,        -- 0未知 1男 2女
  status SMALLINT DEFAULT 1,        -- 1正常 0禁用
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_user_created ON "user"(created_at);

-- 身体档案
CREATE TABLE body_profile (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT UNIQUE REFERENCES "user"(id) ON DELETE CASCADE,
  gender SMALLINT NOT NULL,         -- 1男 2女
  height_cm NUMERIC(5,1) NOT NULL, -- 身高
  birth_year SMALLINT,
  age SMALLINT,
  current_weight NUMERIC(5,1),     -- 当前体重kg
  target_weight NUMERIC(5,1),
  target_type SMALLINT DEFAULT 1,   -- 1减脂 2增肌 3维持
  activity_level SMALLINT DEFAULT 2,-- 1卧床 2久坐 3轻度 4中度 5高度
  bmr NUMERIC(7,1),                -- 基础代谢
  target_calories INTEGER,          -- 每日热量预算
  goal_pace SMALLINT DEFAULT 1,     -- 每周目标kg
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_body_user ON body_profile(user_id);

-- 体重记录
CREATE TABLE weight_record (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id) ON DELETE CASCADE,
  weight NUMERIC(5,1) NOT NULL,
  record_at DATE NOT NULL,
  source SMALLINT DEFAULT 1,        -- 1手动 2智能秤
  note TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_weight_user_date ON weight_record(user_id, record_at DESC);

-- 食物库
CREATE TABLE food (
  id BIGSERIAL PRIMARY KEY,
  name VARCHAR(128) NOT NULL,
  category VARCHAR(64),
  calories_100g NUMERIC(7,1) NOT NULL, -- 每100g热量
  protein_100g NUMERIC(6,2),
  fat_100g NUMERIC(6,2),
  carb_100g NUMERIC(6,2),
  gi SMALLINT,                       -- 血糖生成指数
  is_standard BOOLEAN DEFAULT FALSE,  -- 是否标准减脂餐
  status SMALLINT DEFAULT 1,          -- 1启用 0停用
  search_vec tsvector GENERATED ALWAYS AS (to_tsvector('simple', coalesce(name,''))) STORED,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_food_name ON food USING gin(search_vec);
CREATE INDEX idx_food_category ON food(category);

-- 食物别名（提升识别匹配率）
CREATE TABLE food_alias (
  id BIGSERIAL PRIMARY KEY,
  food_id BIGINT REFERENCES food(id) ON DELETE CASCADE,
  alias VARCHAR(128) NOT NULL UNIQUE
);

-- 饮食记录
CREATE TABLE meal_record (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id) ON DELETE CASCADE,
  record_date DATE NOT NULL,
  meal_type SMALLINT NOT NULL,     -- 1早餐 2午餐 3晚餐 4加餐
  food_id BIGINT REFERENCES food(id),
  food_name_snapshot VARCHAR(128), -- 快照，防食物库变更
  amount_g NUMERIC(7,1) NOT NULL, -- 分量克
  calories NUMERIC(8,1) NOT NULL, -- 热量快照
  protein NUMERIC(7,2),
  fat NUMERIC(7,2),
  carb NUMERIC(7,2),
  confidence NUMERIC(4,2),        -- 识别置信度
  source SMALLINT DEFAULT 1,       -- 1拍照 2语音 3手动 4AI推荐
  image_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_meal_user_date ON meal_record(user_id, record_date DESC, meal_type);
CREATE INDEX idx_meal_food ON meal_record(food_id);

-- 运动记录
CREATE TABLE sport_record (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id) ON DELETE CASCADE,
  sport_name VARCHAR(128),
  met NUMERIC(4,2),
  duration_min INTEGER NOT NULL,
  calories NUMERIC(8,1) NOT NULL,
  source SMALLINT DEFAULT 1,       -- 1手动 2手环 3标准项目
  record_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_sport_user ON sport_record(user_id, record_at DESC);

-- 步数记录
CREATE TABLE step_record (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id) ON DELETE CASCADE,
  record_date DATE NOT NULL,
  steps INTEGER NOT NULL,
  source SMALLINT DEFAULT 1,        -- 1微信 2手环
  hourly_json JSONB DEFAULT '{}'::jsonb, -- 逐时步数，用于校准
  calibrated_met NUMERIC(4,2),      -- 校准后MET
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, record_date)
);
CREATE INDEX idx_step_user_date ON step_record(user_id, record_date DESC);

-- 每日热量快照
CREATE TABLE daily_snapshot (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id) ON DELETE CASCADE,
  snapshot_date DATE NOT NULL,
  bmr NUMERIC(7,1),
  pal NUMERIC(3,2),
  neat NUMERIC(7,1),
  eat NUMERIC(7,1),
  tef NUMERIC(7,1),
  tee NUMERIC(7,1),
  intake NUMERIC(7,1) DEFAULT 0,
  deficit NUMERIC(8,1) DEFAULT 0,
  steps INTEGER DEFAULT 0,
  calories_burnt NUMERIC(8,1) DEFAULT 0,
  calibration_used BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, snapshot_date)
);
CREATE INDEX idx_snap_user_date ON daily_snapshot(user_id, snapshot_date DESC);

-- 商家
CREATE TABLE merchant (
  id BIGSERIAL PRIMARY KEY,
  name VARCHAR(128) NOT NULL,
  category VARCHAR(64) NOT NULL,   -- 轻食店/便利店/健身房/场馆等
  address TEXT,
  geo GEOMETRY(Point, 4326),       -- 经纬度（可选postgis，否则存lat/lng字段）
  lat NUMERIC(10,7),
  lng NUMERIC(10,7),
  phone VARCHAR(32),
  rating NUMERIC(3,1) DEFAULT 5.0,
  status SMALLINT DEFAULT 1,       -- 1营业 0停业
  audit_status SMALLINT DEFAULT 0, -- 0待审 1通过 2驳回
  owner_user_id BIGINT REFERENCES "user"(id),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_merchant_geo ON merchant(lat, lng);
CREATE INDEX idx_merchant_category ON merchant(category);

-- 标准目录
CREATE TABLE sku_catalog (
  id BIGSERIAL PRIMARY KEY,
  code VARCHAR(32) UNIQUE NOT NULL,  -- FD-001 等
  name VARCHAR(128) NOT NULL,
  category VARCHAR(64),
  calories_low INTEGER,
  calories_high INTEGER,
  base_price NUMERIC(8,2) NOT NULL,
  min_price NUMERIC(8,2) NOT NULL,
  max_price NUMERIC(8,2) NOT NULL,
  unit VARCHAR(32),
  status SMALLINT DEFAULT 1,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 商家SKU
CREATE TABLE merchant_sku (
  id BIGSERIAL PRIMARY KEY,
  merchant_id BIGINT REFERENCES merchant(id) ON DELETE CASCADE,
  catalog_id BIGINT REFERENCES sku_catalog(id),
  price NUMERIC(8,2) NOT NULL,
  stock INTEGER DEFAULT -1,        -- -1无限
  status SMALLINT DEFAULT 1,       -- 1上架 0下架
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_ms_merchant ON merchant_sku(merchant_id);
CREATE UNIQUE INDEX uk_ms ON merchant_sku(merchant_id, catalog_id);

-- 券
CREATE TABLE coupon (
  id BIGSERIAL PRIMARY KEY,
  code VARCHAR(64) UNIQUE NOT NULL,   -- 核销码
  type SMALLINT NOT NULL,             -- 1满减 2折扣 3免费 4体验
  scope SMALLINT NOT NULL,            -- 1吃 2动 3异业 4通用
  amount NUMERIC(8,2) DEFAULT 0,      -- 减免金额
  discount_rate NUMERIC(4,2),         -- 折扣
  min_spend NUMERIC(8,2) DEFAULT 0,
  merchant_id BIGINT REFERENCES merchant(id),
  sponsor SMALLINT DEFAULT 1,         -- 1商家 2平台
  obtain_way SMALLINT DEFAULT 1,      -- 1邀请 2任务 3平台补贴 4注册礼
  obtain_user_id BIGINT REFERENCES "user"(id),
  status SMALLINT DEFAULT 1,          -- 1未用 2已用 3过期 4作废
  valid_from TIMESTAMPTZ,
  valid_to TIMESTAMPTZ,
  used_at TIMESTAMPTZ,
  order_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_coupon_user ON coupon(obtain_user_id, status);
CREATE INDEX idx_coupon_merchant ON coupon(merchant_id);

-- 订单
CREATE TABLE "order" (
  id BIGSERIAL PRIMARY KEY,
  order_no VARCHAR(64) UNIQUE NOT NULL,
  user_id BIGINT REFERENCES "user"(id),
  merchant_id BIGINT REFERENCES merchant(id),
  total_amount NUMERIC(10,2) NOT NULL,
  discount_amount NUMERIC(10,2) DEFAULT 0,
  pay_amount NUMERIC(10,2) NOT NULL,
  coupon_id BIGINT REFERENCES coupon(id),
  status SMALLINT DEFAULT 1,        -- 1待支付 2已支付待核销 3已完成 4已取消 5已退款
  pay_at TIMESTAMPTZ,
  expire_at TIMESTAMPTZ,
  redeem_code VARCHAR(64) UNIQUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_order_user ON "order"(user_id, created_at DESC);
CREATE INDEX idx_order_merchant ON "order"(merchant_id, status);

-- 核销日志
CREATE TABLE redeem_log (

  status SMALLINT DEFAULT 1,       -- 1招募中 2满员 3进行中 4结束
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_battle_city ON battle(city, meet_at);

-- 挑战赛
CREATE TABLE challenge (

CREATE TABLE challenge_join (
```

## 7.3 关键关系与约束

- 所有业务表带 `user_id` 的业务数据必须行级隔离（查询默认带 user_id 条件），防止越权。
- `daily_snapshot` 唯一约束 `(user_id, snapshot_date)`，幂等写入。
- `invite.invitee_id` 唯一：一人只能被邀请一次。
- 订单金额一致性：服务端重算 `pay_amount = total_amount - discount_amount`，不信任前端。
- 核销码唯一索引，防止重复核销。

## 7.4 归档策略

超过 2 年的 `meal_record`、`sport_record`、`ai_dialog` 按月分区归档到历史表 `xxx_archive_YYYYMM`，热表只留近期数据。首期数据量小可不实施，但表结构预留 `created_at` 便于后续分区。
