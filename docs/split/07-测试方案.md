# 07 · 测试方案

> 拆分自《AI 饮食管控教练 · 全栈开发交付文档》第九部分，内容为原文。

## 9.1 测试分层

单元测试（后端 pytest，覆盖服务层与计算逻辑）≥ 70% 行覆盖；接口测试（pytest + httpx）；前端组件测试（Vitest + uni-app 测试库）；E2E（微信开发者工具自动化 + Playwright 测 H5）。

## 9.2 功能测试

- 建档：各字段边界（身高 0/200、体重 0/500、年龄负数）均校验。
- 热量计算：覆盖 5 种活动水平 × 男女 × 各餐摄入组合，结果对照 Excel 手算表（附件 `calorie_test_cases.xlsx`【假设】需自造一份 50 行用例）。
- 拍照识别：准备 30 张测试图（食堂餐盘 10、外卖 10、便利店 10），记录识别准确率、分量估算误差。
- 步数校准：模拟 0/3000/8000/12000/20000 步，校验 NEAT 落在合理区间。
- 商家定价：上边界、下边界、越界各一条，越界必返回 400。
- 券：过期、未达门槛、非本商家、重复使用各一条用例。
- 邀请：自邀请、同设备、重复绑定、达上限各一条。

## 9.3 兼容性测试

- 微信开发者工具：模拟 iPhone 6/7/8、iPhone X、iPhone 12 Pro、iPad、Android 主流机型。
- 真机：至少 2 台 iOS、2 台 Android；覆盖微信 8.x 与最新版。
- 管理后台 H5：Chrome、Edge、Safari 最新版 + 1920/1440/375 三档宽度。
- 网络：4G/弱网/断网，验证本地缓存与重试。

## 9.4 性能测试

- 单接口 P95 < 300ms（查询）、< 800ms（写+重算）。
- AI 对话 P95 < 3s，超时降级。
- 首页首屏（含账户重算）< 1.5s。
- 压测：100 并发持续 5 分钟，错误率 < 1%，无内存泄漏。
- 数据库：单表 100 万行下分页查询 < 500ms。

## 9.5 安全测试

- 越权：用用户 A 的 token 访问用户 B 的记录接口，必返 1002。
- SQL 注入：所有列表查询入参用 `' or 1=1--` 等 payload 测试，无异常返回。
- XSS：动态内容中插入 `<script>`，存储后展示必须转义。
- 内容安全：违规词、违规图触发审核拦截。
- 接口重放：相同请求 1 秒内发 10 次，仅首次成功。
- 支付：篡改 `pay_amount` 或重复回调，订单金额不变、不重复发货。

## 9.6 Bug 等级与处理

| 等级    | 定义                 | 修复时限   |
| ----- | ------------------ | ------ |
| P0 致命 | 数据错算、支付/核销漏洞、崩溃、越权 | 24 小时内 |
| P1 严重 | 主流程阻塞、AI 不可用、数据丢失  | 3 天内   |
| P2 一般 | 样式错乱、文案错、交互别扭      | 下个迭代   |
| P3 轻微 | 错别字、建议类            | 排期处理   |

## 9.7 上线通过标准（Go-No-Go）

- P0/P1 全部关闭，无遗留。
- 接口测试 100% 通过，单测覆盖 ≥ 70%。
- 性能达标，安全测试无高危。
- 冒烟用例 50 条全部通过。
