## 一、AI 相关需求与验收

### 1.1 项目目标中的 AI 能力（原文：1.2 项目目标）

2. **AI 饭点决策引擎**：食堂/外卖/便利店场景下拍照菜单，AI 推荐最优组合并一键记录。
3. **AI 主动介入**：覆盖 12+ 触发场景（餐前提醒、下午茶防诱惑、深夜防崩塌、超标后运动建议等），通过订阅消息推送。
4. **AI 对话咨询**：回答"饿了能吃什么""这菜油多吗""今天为什么没瘦"等问题，邀请扩容机制。

### 1.2 功能清单（原文：2.1 功能清单与优先级）

- **P0**：拍照记录、TDEE 计算、AI 对话（含次数限制与邀请扩容）、饭点决策（菜单拍照识别+推荐）。
- **P1（上线后 1 个月内）**：人工教练工单、平台自营 AI+真人教练订阅付费、智能推荐。

### 1.3 主流程中的 AI 环节（原文：2.3.1 主流程）

3. 每日 3-5 次：拍照记录饮食 → 视觉识别 → 用户确认/修正分量 → 写入摄入 → 热量账户环形图实时更新。
4. 饭点（11:00、17:00）推送：引导拍照或 AI 推荐。
7. 每周生成热量控制周报（含缺口、步数、体重趋势、AI 点评）。

### 1.4 异常场景（原文：2.4 异常场景）

| 场景        | 处理方式                                      |
| --------- | ----------------------------------------- |
| 拍照识别失败/模糊 | 提示"没看清，换个角度再拍或手动搜索"，保留手动录入入口              |
| AI 服务超时   | 前端提示"AI 正在思考，稍后再问"，降级为预设 FAQ 回答           |

### 1.5 验收标准（原文：2.5 验收标准）

- 拍照记录写入后，环形图"已摄入"与明细同步更新，无延迟超过 1 秒。
- AI 对话次数用完时，输入框上方展示"今日剩余 0 次，邀请好友解锁"，无法发送。

### 1.6 关键业务指标（原文：1.6）

拍照识别成功率 > 85%、AI 问答满意度 > 4.5/5。

## 二、AI 技术选型与架构

### 2.1 AI 技术选型（原文：6.1 技术选型表 AI 行）

| 层     | 选型                                                  | 理由                                             |
| ----- | --------------------------------------------------- | ---------------------------------------------- |
| AI    | 视觉识别：腾讯云/阿里云图像识别（食物类目）+ DeepSeek / 通义千问 API（对话+RAG） | 成本可控、准确率满足 MVP                                 |

补充（原文：6.1 消息队列行）：消息队列 Redis Streams（首期）→ RabbitMQ（二期），用于异步 AI 调用、提醒推送。

### 2.2 系统分层中的 AI 服务（原文：6.2 系统分层）

```
   ├── AI 服务（对话、饭点决策、RAG、视觉识别）
```

### 2.3 视觉识别 + 知识库（原文：6.3.2，核心设计）

- 食物库：`food` 表 1700+ 条，含热量、蛋白、脂肪、碳水、GI、分类；搜索走 PostgreSQL 全文检索 `tsvector` + 别名表 `food_alias`。
- 识别流程：上传照片 → COS → 视觉 API 返回候选类目 → 匹配 `food` 表 → 置信度 < 0.7 时让用户确认 → 写入记录。
- AI 对话：LangChain + Milvus/PGVector（【假设】首期用 PGVector 省一套组件）+ RAG 检索知识库；系统提示词固定：身份为"AI 饮食教练"、只答体重管理、超限/疾病类引导就医。

### 2.4 AI 限流（原文：6.3.6 安全）

- 限流：全局 100 次/分钟/IP；AI 对话 20 次/分钟/用户；登录 10 次/分钟/IP。

### 2.5 前后端业务闭环（原文：5.7 相关行）

| 前端模块       | 后端服务                | 闭环说明                                 |
| ---------- | ------------------- | ------------------------------------ |
| 拍照识别       | 视觉识别 API + 食物营养库    | 识别→食物库匹配→热量/营养素→用户确认修正→数据沉淀          |
| AI 教练卡/对话  | AI 分诊服务 + RAG + 知识库 | 档案+知识图谱→方案→次数配额→超限转人工                |
| 邀请解锁       | 邀请裂变服务              | 邀请→双方得券→AI 次数扩容→防刷校验                 |

## 三、AI 相关数据表

### 3.1 AI 对话表（原文：7.2 建表 SQL 节选）

```sql
-- AI 对话
CREATE TABLE ai_dialog (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES "user"(id),
  session_id UUID DEFAULT uuid_generate_v4(),
  role VARCHAR(16) NOT NULL,       -- user/assistant
  content TEXT NOT NULL,
  intent VARCHAR(64),
  tokens INTEGER,
  model VARCHAR(64),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_ai_session ON ai_dialog(session_id, created_at);

-- AI 知识库（RAG）
CREATE TABLE ai_knowledge (
  id BIGSERIAL PRIMARY KEY,
  category VARCHAR(64),
  title VARCHAR(256),
  content TEXT NOT NULL,
  embedding vector(1536),          -- 需pgvector扩展，【假设】首期可存为jsonb占位
  source VARCHAR(256),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 3.2 AI 相关字段的其他表

- `meal_record.confidence NUMERIC(4,2)`：识别置信度；`source SMALLINT`（1拍照 2语音 3手动 4AI推荐）。（原文：7.2）
- `user_benefit.ai_times_left INTEGER DEFAULT 10`、`ai_times_reset_at TIMESTAMPTZ`：AI 对话次数配额。（原文：7.2）
- `food` 表含 `search_vec tsvector` 全文检索列与 `food_alias` 别名表，服务视觉识别匹配。（原文：7.2）

### 3.3 归档策略（原文：7.4）

超过 2 年的 `meal_record`、`sport_record`、`ai_dialog` 按月分区归档到历史表 `xxx_archive_YYYYMM`。

## 四、AI 相关接口

### 4.1 接口清单（原文：8.3 接口列表节选）

| #   | 方法     | 路径                  | 说明              |
| --- | ------ | ------------------- | --------------- |
| 7   | POST   | /api/food/search    | 食物搜索            |
| 8   | POST   | /api/meal/recognize | 拍照识别食物          |
| 16  | POST   | /api/ai/chat        | AI 对话（流式可选）     |
| 17  | GET    | /api/ai/times       | 查询剩余对话次数        |
| 18  | POST   | /api/ai/recommend   | 饭点决策推荐          |

相关错误码（原文：8.2）：`4001 余额/次数不足`、`6001 AI 服务暂不可用`。

### 4.2 拍照识别（原文：8.4.2）

**POST /api/meal/recognize**
请求：`multipart/form-data` 字段 `image`（文件）
返回：

```json
{
  "code": 0,
  "data": {
    "request_id": "r-xxx",
    "items": [
      {"food_id": 208, "name": "清蒸鱼", "confidence": 0.92, "amount_g": 150, "calories": 180},
      {"food_id": 512, "name": "红烧肉", "confidence": 0.61, "amount_g": 100, "calories": 320}
    ],
    "need_confirm": true
  }
}
```

### 4.3 AI 对话（原文：8.4.6）

**POST /api/ai/chat**
请求：`{"session_id": "uuid", "message": "下午饿了能吃什么"}`
返回（流式 SSE 或普通 JSON）：

```json
{
  "code": 0,
  "data": {
    "reply": "建议先喝一杯水，15分钟还不饱再吃个水煮蛋或黄瓜，热量低还顶饱。",
    "intent": "hunger_rescue",
    "times_left": 9,
    "references": ["knowledge:1203"]
  }
}
```

若次数用尽，返回 `code: 4001`，`message: "今日对话次数已用完，邀请好友可解锁更多"`，前端展示邀请入口。

### 4.4 鉴权与限流（原文：8.5）

AI 对话额外校验 `user_benefit.ai_times_left`，不足返回 4001。

## 五、AI 相关测试要求

（原文：9.1 测试分层、9.2 功能测试、9.4 性能测试节选）

- 拍照识别：准备 30 张测试图（食堂餐盘 10、外卖 10、便利店 10），记录识别准确率、分量估算误差。
- 里程碑 M2 验收（原文：11.3）：AI 能回答 10 类常见问题，识别测试集准确率 ≥ 85%。
- AI 对话 P95 < 3s，超时降级。
- 监控指标含 AI 调用成本、AI 日成本超预算告警（原文：6.4、10.7）。

## 六、AI 相关默认决策

（原文：13.3 业务默认、13.4 代码与工程默认节选）

- AI 识别置信度 < 0.7：必须让用户确认/修正。
- AI 服务不可用：降级返回预设 FAQ，不卡死。
- 如遇到技术方案确实需要确认且影响大的（如是否引入 pgvector）：默认选最简单的实现（【假设】首期存 jsonb 占位），在 PR 中说明后续可替换，**先做出来再优化**。
- 免责（原文：1.5）：所有 AI 输出均带"仅供参考，具体请遵医嘱"免责声明；不做医疗诊断、不开处方。
