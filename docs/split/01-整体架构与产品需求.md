# 第一部分：项目概述

## 1.1 背景

国内成人超重率 34.3%、肥胖率 16.4%，合计超重肥胖人群超 6 亿。体重管理市场已超 3260 亿元，年均复合增长率 15% 以上。但超 7 成人主动尝试过体重管理，仅 19.3% 能达成目标，6 成年轻人在 3 个月内放弃。核心矛盾是"知道该做，但做不到"——用户缺的不是记录工具，而是每一次饭点、每一次饥饿、每一次动摇时主动介入的 AI 教练。

## 1.2 项目目标

做一个微信小程序（首期）+ 后续原生 App 预留的体重管理平台，核心能力：

1. **热量账户**：以"摄入 - 消耗 = 缺口"为底层逻辑，首页环形图展示今日还能吃多少，拍照即记录。
2. **AI 饭点决策引擎**：食堂/外卖/便利店场景下拍照菜单，AI 推荐最优组合并一键记录。
3. **AI 主动介入**：覆盖 12+ 触发场景（餐前提醒、下午茶防诱惑、深夜防崩塌、超标后运动建议等），通过订阅消息推送。
4. **AI 对话咨询**：回答"饿了能吃什么""这菜油多吗""今天为什么没瘦"等问题，邀请扩容机制。
5. **运动与能量消耗**：步数同步、运动记录、能量消耗模型（TEE = BMR×PAL + EAT + TEF；步数校准只调 NEAT/PAL，不改 TEE 结构）、步数校准。
6. **五种社交**：监督、兴趣社群、约战、挑战赛、动态。
7. **商家标准化生态**：标准目录制 + 价格区间制 + 统一券池 + 商家极简后台。
8. **分层收费 + 邀请解锁**：基础免费 / 进阶 29 元 / 高级 59 元 / 最高档终身，全部可邀请解锁。

## 1.3 目标用户

| 用户群       | 核心痛点             |
| --------- | ---------------- |
| 职场白领      | 不知道吃啥、饿了扛不住、没空运动 |
| 学生党       | 食堂不透明、夜宵诱惑、没人监督  |
| 反复减肥失败者   | 管不住嘴、坚持不了        |
| 中老年慢病人群   | 不知道怎么吃、需要简单+有人盯着 |
| 健身增肌/减脂人群 | 营养运动要配合、需要精确数据   |

## 1.4 项目范围（首期 MVP）

**要做**：微信小程序用户端全部功能 + 后端全套服务 + 管理后台（商家端+平台端合并，先做轻量版）+ 数据库 + 部署上线。

**不做（二期）**：原生 App、iOS/Android 双端、开放平台、多语言、国际化、小程序外的其他形态。

## 1.5 不做清单（明确排除）

- 不做医疗诊断、不开处方、不替代医生。【假设】所有 AI 输出均带"仅供参考，具体请遵医嘱"免责声明。
- 不做在线支付以外的结算（如线下现金、转账）。
- 不做自营电商仓储物流，只做 CPS 导流 + 券核销。
- 不做视频直播、不做 IM 实时音视频（人工教练用异步工单消息，不发语音/视频）。
- 不做复杂权限体系（首期只有用户/商家/平台运营三种角色，不做 RBAC 多角色动态授权）。
- 不做多门店连锁的深度 ERP（商家只管自己门店的上品、定价、券、订单）。

## 1.6 关键业务指标（开发阶段需埋点）

新用户 7 日留存 > 25%、邀请 K 因子 > 0.5、商家扫码转化率 > 15%、拍照识别成功率 > 85%、AI 问答满意度 > 4.5/5、内容获客成本 < 20 元/人。

# 第二部分：产品需求 PRD

## 2.1 功能清单与优先级

**P0（必须，首期交付）**：微信登录、身体档案建档、热量账户首页、拍照记录、饮食记录 CRUD、运动记录、步数同步、TDEE 计算、AI 对话（含次数限制与邀请扩容）、饭点决策（菜单拍照识别+推荐）、商家列表与详情、标准 SKU 目录、券池（用户领券/用券）、订单（创建/支付/核销）、体重记录与趋势、提醒订阅、邀请裂变、社区动态与五种社交（基础版）、管理后台（用户/商家/订单/券基础管理）、埋点上报。

**P1（上线后 1 个月内）**：人工教练工单、平台自营 AI+真人教练订阅付费、商家权重排名、智能推荐、热力与报表后台、社区内容审核。

**P2（后续）**：数据飞轮微调、开放 API、原生 App。

## 2.2 角色与权限

| 角色        | 能做什么                                                  |
| --------- | ----------------------------------------------------- |
| 普通用户（C 端） | 记录、查看热量账户、AI 对话、查看/下单商家、社交、邀请、领券用券                    |
| 商家        | 登录商家后台、选品、在区间内定价、选券、上架/下架、查看核销、处理预约                   |
| 平台运营      | 管理后台全部：标准目录维护、商家入驻审核、价格区间设置、券池管理、内容审核、订单监控、数据看板、补贴券发放 |
| 真人健身教练    | 登录教练端、查看被分配用户的档案与记录、回复工单、复核方案、发动态                     |

## 2.3 核心业务流程

### 2.3.1 主流程：建档 → 每日使用 → 形成闭环

1. 微信授权登录 → 完善身体档案（性别/身高/体重/年龄/目标/活动水平） → 系统计算 BMR、目标热量预算、每日目标步数。
2. 每日早晨：首页弹"今天什么状态"（卧床/久坐/轻度/中度/高度五选一），或用户不点则用默认 PAL。
3. 每日 3-5 次：拍照记录饮食 → 视觉识别 → 用户确认/修正分量 → 写入摄入 → 热量账户环形图实时更新。
4. 饭点（11:00、17:00）推送：引导拍照或 AI 推荐。
5. 运动中/后：步数自动同步、手动添加运动 → 写入消耗 → 环形图"收入项"增加。
6. 深夜推送：当日缺口达成提醒 + 防崩塌话术。
7. 每周生成热量控制周报（含缺口、步数、体重趋势、AI 点评）。

### 2.3.2 商家下单流程

拍照/菜单识别/标准 SKU/附近商家 → 商家详情页 → 选标准 SKU 或菜品 → 确认订单（校验价格区间、选择可用券）→ 微信支付 → 到店出示核销码 → 商家扫码核销 → 订单完成 → 商家获贡献分 + 摄入记录自动写入 + 生成社区经验卡。

### 2.3.3 邀请裂变流程

用户分享带参二维码 → 被邀请人注册并完善档案 → 双方各得券；邀请人累计达 2/5/10 人分别解锁进阶版 90 天/180 天/永久（最高档终身教练）。【假设】防刷规则：被邀请人需完成 1 次拍照记录才算有效，同设备只算 1 次，单人奖励上限 180 天。

## 2.4 异常场景

| 场景        | 处理方式                                      |
| --------- | ----------------------------------------- |
| 拍照识别失败/模糊 | 提示"没看清，换个角度再拍或手动搜索"，保留手动录入入口              |
| 食物库查不到    | 提示"这是新菜？手动填热量或先跳过"，进入用户自定义食物（仅本人可见，标记待审核） |
| AI 服务超时   | 前端提示"AI 正在思考，稍后再问"，降级为预设 FAQ 回答           |
| 微信步数取不到   | 用 PAL 系数估算 NEAT，提示"绑定手环更精准"               |
| 支付中断      | 订单保留 15 分钟，超时自动取消并释放券，可重新下单               |
| 券过期/不可用   | 下单页灰显该券并标注原因（过期/不满足门槛/商家不支持）              |
| 网络异常      | 全局 toast，关键操作（记录、订单）本地缓存，恢复后重试            |
| 用户未授权订阅消息 | 引导跳转设置页开启，不阻断核心流程                         |
| 商家停业/已核销  | 订单详情提示"商家暂不可用"，支持退款入口（走客服工单）              |
| 邀请人达上限    | 提示"已达邀请奖励上限，感谢推广"                         |

## 2.5 验收标准（每条对应测试用例）

- 建档后首页热量账户环形图数值 = BMR×PAL - 已摄入 + 运动消耗 - TEF，误差 0。
- 拍照记录写入后，环形图"已摄入"与明细同步更新，无延迟超过 1 秒。
- AI 对话次数用完时，输入框上方展示"今日剩余 0 次，邀请好友解锁"，无法发送。
- 邀请 2 人（有效）后，用户权益变更为进阶版 90 天，首页/我的可见权益标签。
- 商家定价超出区间，后台保存时接口返回 422 + code 2001，前端提示"请在 ¥X-¥Y 之间定价"。
- 券核销码只能使用一次，重复使用返回"已核销"。
- 步数为 0 时，NEAT 用默认 PAL 估算；步数 > 0 时，按步数校准公式重算。
- 所有页面在 iPhone SE（小屏）与 iPad 上无横向溢出、无截断。

## 3.2 底部 Tab（5 个）

首页、吃什么、运动、社区、我的。中心 FAB 悬浮按钮为"拍照记录"。

## 3.3 跳转关系要点

- 首页 → 任何需要登录的页，未登录先跳 /pages/login，登录后回跳原页。
- 商家详情 → 订单确认（带商家 ID、SKU ID、默认选中券）→ 微信支付 → 支付结果页 → 订单列表。
- 约战详情 → 一键跳转对应场馆商家详情（关联预约与券）。
- 券包 → 点击可用券 → 跳转对应商家/标准 SKU 下单页（自动带券）。
- 邀请裂变 → 生成带参数海报 → 保存本地/转发好友 → 被邀请人落地页自动绑定邀请人。
- 全部页面异常态统一：加载中（骨架屏）、空（插画+引导按钮）、错误（插画+重试按钮）、无权限（提示登录/开通权益）。
