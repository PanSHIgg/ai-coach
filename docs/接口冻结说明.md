## 三、Phase 5 契约新增（已由主 Agent 单点落地）

### 3.1 新接口
| 接口 | 说明 |
| --- | --- |
| `POST /api/track` | 埋点事件批量上报（`security: []` 允许匿名，单次 ≤50 条）；返回 `{accepted}`。见 `app/api/v1/endpoints/track.py`、`app/schemas/track.py` |
| `POST /api/order/{id}/refund` | 申请退款（已支付待核销 2 → 已退款 5，**幂等**：已退款重复申请仍成功）；`RefundIn{reason?}`、`RefundData{order_id,status,refunded}`。见 `app/api/v1/endpoints/orders.py`、`services/order_service.refund_order` |

### 3.2 新错误码与幂等头
- **错误码 `4002 重复请求`**：定义于 `app/schemas/common.py::ErrorCode.DUPLICATE_REQUEST`，HTTP 409。
- **幂等头 `Idempotency-Key`**（约定见 `backend/app/core/idempotency.py`）：
  - 写接口（`POST/PUT/PATCH/DELETE` 且路径以 `/api` 开头）由客户端携带 `Idempotency-Key`（每个逻辑操作
    一个唯一值，通常 UUID）；
  - 同一 key 在 `IDEMPOTENCY_TTL_SECONDS`（默认 300s）窗口内**仅首次放行**，重复返回 **HTTP 409 + code 4002**；
  - **不带该头的请求行为完全不变**（既有客户端/测试零影响）；
  - 去重键含调用方身份指纹（Authorization 的 sha256 前缀），防他人抢占 key；存储优先 Redis `SET NX EX`，
    Redis 不可用时降级进程内字典；
  - 装配入口：`app/main.py`（`install_idempotency` / `add_middleware(IdempotencyMiddleware, ...)`）。
  - 该机制闭环了 F6 安全报告记录的「接口重放」P1 缺口（详见 `docs/安全测试报告.md`、`docs/go-no-go.md` §2.1）。
  - **失败即释放（P2-10）**：若首次请求以 4xx/5xx 结束或抛异常，立即释放该 key，
    客户端可用**同一个 key** 安全重试；成功（<400）才持续占用。

### 3.3 客户端接入现状（P2-2 澄清）

> **当前 miniapp / admin 客户端均未发送 `Idempotency-Key`**，故上述幂等机制是**「协作式幂等」**，
> 而非服务端强制防重放：服务端仅在客户端主动携带该头时生效，不带头的写请求行为完全不变。
> 因此**无 key 时的重放风险由「支付/核销状态机 + 限流 + 内容审核」兜底**（订单状态机天然阻止二次推进、
> 限流抑制高频重放、内容审核拦截重放产生的重复内容），并非仅依赖幂等键。

**客户端接入建议**：写操作（下单/支付/发帖等）在发起前生成一个唯一 key（UUID）并**在同一次逻辑操作
的所有重试中复用同一个 key**；成功后丢弃、失败重试继续用同一 key（服务端已在失败时释放占用）。

## 四、变更纪律（契约单点 + 四处同步）

契约由**主 Agent 单点修改并冻结**，子 Agent 一律不得改契约；禁止实现单方面漂移（AGENTS §4.3）。
任何契约变更必须**同一次**同步以下四处：

1. `contracts/openapi.yaml`（真源，先改）；
2. 后端 pydantic schema（`backend/app/schemas/*`）与响应模型；
3. TS 类型**两份手写副本**：`contracts/ts/api.d.ts` 与 `miniapp/src/types/api.d.ts`（**必须逐字一致**）；
4. `contracts/mock/routes.mjs`（新增接口须补 canned data，覆盖全部 method+path）。

同步后运行 F2 门禁复验（见下），四处比对全绿方可提交。

## 七、热修流程（冻结后）

1. 发现缺陷 → 主 Agent 判定是否触及契约；
2. **不触及契约**（仅实现/bugfix）：走常规修复 + 测试，不改 `contracts/`；
3. **触及契约**：主 Agent 单点改 `openapi.yaml` → 同步 pydantic/TS 双副本/Mock（§四）→ 跑 F2 门禁 + 全量 pytest；
4. 门禁全绿 + 主 Agent 干净环境复跑通过 → 提交；契约变更在提交信息中显式标注（版本号/新增/破坏性变更）；
5. 破坏性变更（删字段/改语义）须评估前后端兼容并通知对端。
