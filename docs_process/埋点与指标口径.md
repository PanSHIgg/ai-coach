# 埋点与指标口径（Phase 5 / F3）

> 真源：`docs/split/01-整体架构与产品需求.md §1.6`（6 项核心指标）、
> `contracts/openapi.yaml`（`POST /api/track`：`TrackEventIn`/`TrackIn`/`TrackData`）、
> 表 `track_event`（`backend/app/models/__init__.py` 的 `TrackEvent`）。
> 聚合报表脚本：`backend/scripts/analytics_report.py`（`--dsn`，输出表 + JSON）。

## 1. 上报接口 `POST /api/track`

- **鉴权**：允许匿名（契约 `security: []`）。带有效 Bearer token → 关联 `user_id`；无/无效 token
  或已删用户 → `user_id` 为 `NULL`（走 `get_optional_user`，不抛 1001）。
- **批量**：一次请求 `events` 为 **1~50** 条；越界 → HTTP 422 / 业务码 `2001`。
- **单事件字段**：`event`（1~64 字符必填）、`properties`（JSON 对象，默认 `{}`）、
  `occurred_at`（可选 ISO8601；缺省用服务端 `NOW()` 落库）。
- **批量字段**：`device_id`（可选，≤64，用于匿名/跨端识别同一设备）、
  `platform`（`1` 小程序 / `2` H5 / `3` admin 后台，默认 `1`）。
- **响应**：`{code:0, data:{accepted:<写入条数>}, ...}`；批量一次提交，不逐行落库。
- 请求示例：

```json
POST /api/track
{
  "platform": 1,
  "device_id": "dev-8f2c...",
  "events": [
    {"event": "scan_in", "properties": {"merchant_id": 12}, "occurred_at": "2026-09-29T12:00:00+08:00"},
    {"event": "order_pay", "properties": {"order_id": 9001, "amount": 29.9}}
  ]
}
```

落库列：`event` / `user_id`(可空) / `device_id` / `platform` / `properties`(JSONB) /
`occurred_at`(TIMESTAMPTZ) / `created_at`(服务端写入时间)。

## 2. 前端（miniapp）应上报的事件名清单

事件名统一用 snake_case、语义单一、可枚举。**属性名固定以支撑报表口径**。

| 事件名 | 触发时机 | 关键属性 | 服务的指标 |
| --- | --- | --- | --- |
| `app_open` / `login` | 冷启动/进入首页、登录成功 | `{from}` | 日活、7 日留存（活跃判定） |
| `register` | 新用户注册完成 | `{}` | 留存 cohort（配合 `user.created_at`） |
| `scan_in` | 扫商家/券码进入 | `{"merchant_id":int,"scene":str}` | 扫码转化率（分母） |
| `order_pay` | 订单支付成功 | `{"order_id":int,"merchant_id":int,"amount":float}` | 扫码转化率（分子） |
| `meal_photo` | 发起拍照记录 | `{"meal_type":int}` | 识别成功率（分母） |
| `ai_recognize` | 识别返回 | `{"success":bool,"confidence":float,"need_confirm":bool}` | 识别成功率（分子/分母） |
| `ai_chat` | 与 AI 完成一次问答 | `{"session_id":str,"intent":str}` | AI 满意度（分母/关联） |
| `ai_rating` | 用户对 AI 回答评分 | `{"score":int(1~5),"session_id":str}` | AI 满意度（分子） |
| `invite_share` | 发起邀请分享 | `{"channel":str}` | K 因子（发起） |
| `invite_accept` | 被邀请人完成注册绑定 | `{"inviter_id":int}` | K 因子（转化） |

约定：
- 匿名可达的事件（`scan_in`）务必带上 `device_id`，否则无法做设备级去重，指标会退化为 `null`。
- 评分类事件属性用数字 `score`（1~5），不要用字符串，报表按 `properties->>'score'` 聚合。
- 事件名不得随意新增同义名（如不要同时用 `pay` 和 `order_pay`），新增需更新本节。

## 3. 六项指标口径

时间窗默认 **Asia/Shanghai（UTC+8）**；「去重」除注明外均按用户/设备去重。

### 3.1 新用户 7 日留存（目标 > 25%）

- **分子**：cohort（注册日 = D 的用户）中，在 **D+7 当日**有活跃事件（`track_event`）的用户数。
- **分母**：注册日 ≤ 今天−7 天、可观测满窗的 cohort 用户数（`user.created_at`）。
- **时间窗**：cohort 日 + 第 7 个自然日（UTC+8 日界）；仅统计满窗 cohort。
- **去重**：用户级（`user_id`）。
- **数据来源**：`user.created_at`（cohort）× `track_event.user_id/occurred_at`（活跃）。
- **就绪度**：⚠️ 依赖前端上报活跃事件（`app_open`/`login`）。当前 `track_event` 为空 → 报表返回 `null`。

### 3.2 邀请 K 因子（目标 > 0.5）

- **分子**：成功邀请数（`invite.invitee_id` 非空，即被邀请人已绑定）。
- **分母**：发起过邀请的去重用户数（`invite.inviter_id` 去重）。
- **口径**：`K = 成功邀请数 / 邀请发起人数`（每个邀请人平均带来的新用户数）。
- **时间窗**：全量累计（可按 `invite.created_at` 加窗）。
- **数据来源**：`invite.inviter_id / invitee_id / status / created_at`。
- **就绪度**：⚠️ 表就绪，但无邀请记录时返回 `null`；需邀请裂变功能产生数据。

### 3.3 商家扫码转化率（目标 > 15%）

- **分子**：扫码去重主体中，产生 `order_pay` 的去重主体数。
- **分母**：上报 `scan_in` 的去重主体数。
- **去重主体**：`COALESCE(device_id, 'u:' || user_id)`（匿名扫码靠 `device_id`）。
- **时间窗**：可配置（默认累计）。
- **数据来源**：`track_event(event='scan_in'/'order_pay', device_id, properties.merchant_id)`。
- **就绪度**：⚠️ 依赖前端上报；无 `scan_in`（或缺少 `device_id` 导致无法识别主体）→ `null`。

### 3.4 拍照识别成功率（目标 > 85%）

- **分子**：`ai_recognize` 事件中 `properties.success = true` 的次数。
- **分母**：上报 `ai_recognize` 且带 `properties.success`（`true`/`false`）的次数。
- **时间窗**：可配置（默认累计）。
- **数据来源**：`track_event(event='ai_recognize', properties.success/confidence/need_confirm)`。
  前端已在识别返回（成功/失败都上报）时打点（见 `docs_process/前端埋点接入说明.md`）。
- **就绪度**：⚠️ **数据源已就绪**（前端已上报 `ai_recognize`）；`track_event` 暂无该事件时
  报表返回 `null` 并注明「待积累」，有数据即真算（口径：`success=true` 占比）。

### 3.5 AI 问答满意度（目标 > 4.5 / 5）

- **分子**：`ai_rating` 事件的 `score` 之和。
- **分母**：有效评分数（`ai_rating` 且 `score` 为 1~5 数字）。
- **时间窗**：可配置（默认累计）。
- **去重**：不做用户去重（按评分条数；如需可加「每会话一次」限制）。
- **数据来源**：`track_event(event='ai_rating', properties.score)`。
- **就绪度**：⚠️ 依赖前端在 AI 回答后引导评分；无评分 → `null`。

### 3.6 内容获客成本 CAC（目标 < 20 元/人）

- **分子**：同期内容/广告投放总花费（元）。
- **分母**：同期新增用户数（`user.created_at` 落在窗口内）。
- **时间窗**：与投放账单周期对齐（默认月）。
- **数据来源**：**外部投放花费**（广告后台/内容投放账单）。库内无花费表。
- **就绪度**：❌ **数据源缺失（外部数据）** → 报表固定 `null`。
  **需补**：导入投放花费（新表或配置），或接入广告平台账单；分母可直接由 `user` 表取。

## 4. 报表脚本

```bash
python backend/scripts/analytics_report.py \
    --dsn "postgresql://postgres:postgres@127.0.0.1:5432/ai_coach"
```

- 输出：人类可读表 + JSON（`metrics[]` 含 `key/name/value/unit/target/ready/source/note`）。
- 原则：能真算的真算；数据源缺失的 `value` 为 `null` 且 `ready=false`，`note` 说明缺什么、需补什么。

## 5. 就绪度总览

| 指标 | 目标 | 当前就绪度 | 关键缺口 |
| --- | --- | --- | --- |
| 新用户 7 日留存 | >25% | ⚠️ 依赖活跃埋点 | 前端上报 `app_open`/`login` |
| 邀请 K 因子 | >0.5 | ⚠️ 表就绪、待数据 | 邀请功能产生 `invite` 记录 |
| 商家扫码转化率 | >15% | ⚠️ 依赖埋点 | 上报 `scan_in`/`order_pay`（带 `device_id`） |
| 拍照识别成功率 | >85% | ⚠️ 数据源已就绪、待积累 | 前端上报 `ai_recognize`（`success/confidence/need_confirm`） |
| AI 问答满意度 | >4.5/5 | ⚠️ 依赖埋点 | 上报 `ai_rating`（`score` 1~5） |
| 内容获客成本 | <20 元/人 | ❌ 外部数据缺失 | 导入投放花费 + 新增用户数 |
