## 二、SQL 注入（本轮新增，`tests/test_security_sqli.py`）

**入口 × payload**（同类 payload 用 `parametrize` 合并，含经典 `' OR '1'='1`、
`'; DROP TABLE "user"; --`、`1 UNION SELECT ...`、`%27`、`--` 注释、堆叠 `pg_sleep`、
4096 超长串）：

| 入口 | 断言 | 实测 |
| --- | --- | --- |
| `POST /api/auth/login`（code 字符串） | 非 500 / 无 SQL 错误泄露 / 正常签发 / 关键表行数不变 | 全部 code=0 |
| `POST /api/food/search`（keyword，tsvector+ILIKE 参数化） | 非 500 / 空结果 / 表行数不变 | 全部 code=0、items=[] |
| `GET /api/meal/list`（page/page_size/page 整型） | 422/2001 | 全部 422 |
| `GET /api/meal/list?date=` | 422/2001 | 全部 422 |
| `GET /api/order/list?status=`、`/api/community/post/list?post_type=` | 422/2001 | 全部 422 |
| `GET /api/community/battle/list?city=`（字符串筛选） | 非 500 / code=0 | 全部 code=0 |
| 路径参数 id：`GET /api/community/post/{id}`、`POST /api/order/{id}/pay`、`DELETE /api/meal/{id}` | 422/2001 | 全部 422 |

**关键点**：每次注入后都**真查库**断言关键表（`user/order/meal_record/food/coupon/
community_post/merchant`）仍存在且业务表行数不变；响应体不含 `syntax error`/`psycopg`/
`asyncpg`/`traceback` 等泄露标记。

**根因**：全仓 SQL 访问均走 SQLAlchemy ORM / 参数化（`app/services/*` 无 f-string 拼 SQL），
注入面天然闭合。结论：无 SQL 注入缺陷。

## 三、接口重放（`tests/test_security_replay.py`）——已闭环 ✅

**期望行为**：同一写入 1 秒内重复 10 次，仅首次成功。

**现状（Phase 5 已修）**：

- 新增 `backend/app/core/idempotency.py`（`IdempotencyMiddleware`）并装配进 `app/main.py`。
- 写接口（`POST/PUT/PATCH/DELETE` 且路径以 `/api` 开头）携带 `Idempotency-Key` 时，同一 key
  在 `IDEMPOTENCY_TTL_SECONDS`（默认 300s）窗口内**仅首次放行**，其余返回
  **HTTP 409 + 业务码 4002**（`DUPLICATE_REQUEST`）。
- **不带该头的请求行为完全不变**（既有客户端零影响）；去重键含 Authorization 头指纹（身份隔离），
  存储优先 Redis `SET NX EX`，不可用时降级进程内字典。
- **失败即释放（P2-10 修复）**：key 在进入路由前占用；若本次响应以 4xx/5xx 结束（如空 body → 422/2001、
  次数不足 4001、500）或下游抛异常，则**立即释放该 key**，使客户端可用**同一个 key** 安全重试；
  仅成功（<400）保持占用。这样「失败重试」不会被 409/4002 误拦，同时成功后的重放仍被拦截。
- **协作式而非服务端强制**：当前 miniapp/admin 客户端**均未发送 `Idempotency-Key`**，故该机制是
  「协作式幂等」，无 key 时的重放风险由「支付/核销状态机 + 限流 + 内容审核」兜底（见
  `docs_process/接口冻结说明.md` §3.2、`docs_process/前端埋点接入说明.md`）。

**实跑**：`test_security_replay.py` → **9 passed，无 xfail**（2026-09-29 16:40 UTC），覆盖
同 key 重放 10 次仅首次成功（下单 / 发帖）、失败后同 key 可重试（非 409/4002）、成功后重放仍 409/4002、
不带 key 不拦截、不同 key 各自成功、身份隔离。

**定级：已闭环（原 P1 缺口已修复并由测试证实）。**
